# Hackathon Demo Pitch

## Principle

The demo must make the best scoring parts obvious. Show the problem, the working product, the required technologies, and the judging evidence without wasting time.

## Demo Workflow

1. Identify the judging criteria and required submission format.
2. Define the opening problem in one clear sentence.
3. Show the core workflow end to end.
4. Highlight required technologies and differentiators.
5. Show data, metrics, dashboard, or before/after impact when relevant.
6. Show reliability, security, or validation only when it improves the score or trust.
7. Close with what was built, why it matters, and what is next.

## Demo Structure

Use this order unless the event format requires another:

1. Problem and user
2. Solution promise
3. Live product walkthrough
4. Technical architecture and required tools
5. Impact and judging proof
6. Limitations and next steps

## Pitch Rules

- Keep the story tied to the hackathon overview and rubric.
- Do not spend demo time on features that are not working.
- Show the most stable path first.
- Have fallback screenshots or recordings for external services.
- Avoid claims that cannot be proven in the product or submission.

## Assets To Prepare

- Demo script
- Video outline
- Screenshots
- Architecture diagram when helpful
- Judging rubric proof points
- Short project description
- Technical highlights
- Known limitations

## Done Check

The demo is ready when a judge can understand the problem, see the product work, recognize rubric fit, and find required evidence in the submission.
