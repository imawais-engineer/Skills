# Hackathon Compliance Review

## Principle

A non-compliant project can lose before judging starts. Check rules early and again before submission.

## Review Workflow

1. List mandatory requirements and confirm each is satisfied or planned.
2. List submission items and confirm each has an owner and status.
3. Check allowed, required, and banned tools or technologies.
4. Check eligibility, team size, location, age, account, track, and deadline constraints when present.
5. Check licensing, open-source, third-party API, data, privacy, and attribution rules.
6. Check demo constraints such as video length, live URL, repo visibility, and documentation format.
7. Check that the project does not violate safety, legal, or platform restrictions.
8. Produce blockers, risks, and fixes.

## Compliance Matrix

For each item, track:

- Source section
- Requirement or rule
- Status: pass, fail, unclear, not started, not applicable
- Evidence
- Fix needed
- Owner or next action

## Hard Stops

Escalate before continuing when there is uncertainty around:

- Eligibility
- Required technology
- Banned tool or dataset
- Copyright or license
- Personal or sensitive data
- Submission deadline
- Required deliverable format

## Final Gate

Before submission, confirm:

- All required deliverables exist.
- The project matches the selected track.
- Required tools or sponsor technologies are used correctly.
- Licenses and attributions are included.
- Demo/repo/deployment links work.
- Rules and requirements are verified.
- Implementation is validated.
