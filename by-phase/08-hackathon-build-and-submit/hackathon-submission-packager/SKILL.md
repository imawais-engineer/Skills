# Hackathon Submission Packager

## Principle

Package only what the competition asks for, but make every required item easy for judges to open, run, and understand.

## Packaging Workflow

1. Extract exact submission requirements from the brief.
2. Create a checklist for each required deliverable.
3. Prepare repository documentation and setup instructions.
4. Prepare demo assets: video, live URL, screenshots, and pitch content when required.
5. Prepare technical notes: architecture, APIs, datasets, required tools, and environment variables.
6. Prepare compliance notes: license, attributions, data usage, and known limitations.
7. Verify every link, file, command, and credential instruction before final submission.

## Common Deliverables

Include only when required or useful:

- Project title and tagline
- Short and long description
- README
- Live demo URL
- Source repository URL
- Demo video
- Screenshots
- Pitch deck
- Architecture notes
- Setup instructions
- `.env.example`
- License and attributions
- Testing checklist
- Judging criteria evidence map
- Devpost or competition form answers

## README Structure

Prefer this order:

1. Project name and one-line value
2. Problem
3. Solution
4. Key features
5. Tech stack and required resources
6. Architecture
7. Setup and environment variables
8. How to run
9. Demo and screenshots
10. Known limitations
11. License and attributions

## Final Submission Gate

Before final submission, verify:

- All required fields are filled.
- All links open.
- The demo path works.
- The repo can be understood by judges.
- Required tools and technologies are named.
- Rules, licenses, and attributions are satisfied.
- Verification and validation are both complete.
